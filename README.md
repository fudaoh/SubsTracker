# 📋 订阅到期提醒

部署在 Cloudflare Workers 上的订阅到期提醒面板。单文件、无构建、数据库用自己的 D1——会员、域名、证书、任何有到期日的东西，到期前按你设定的节奏每天推送提醒到 **Telegram** 和 **Server 酱（微信）**。

- ✅ 单文件部署：整份粘贴到 Workers 编辑器即可，无需 npm / wrangler
- ✅ 管理面板：统计卡片、订阅增删改、批量测试/删除、渠道独立开关
- ✅ 通知节奏自定义：从「通知时间」起连发 N 天（1~365），连发完自动回待提醒，改结束时间即开启新一轮
- ✅ 双渠道推送 + 分渠道测试，发送失败自动重试
- ✅ 安全设计：SHA-256 口令哈希、Session 令牌、登录限速、CSRF 防护

## 🚀 部署（约 5 分钟）

### 1. 创建 Worker 并粘贴代码

Cloudflare Dashboard → **Workers 和 Pages** → 创建 Worker → 编辑代码，将 [`1.js`](./1.js) 的全部内容粘贴进去（替换默认代码）→ **部署**。

### 2. 绑定 D1 数据库

Workers → 你的 Worker → **设置 → 绑定** → 添加 D1 数据库：

| 项目 | 值 |
|---|---|
| 变量名称 | `DB`（必须大写） |
| D1 数据库 | 新建一个即可 |

数据表（subs / config / sessions / login_lock）会在首次访问时自动创建，无需手动建表。

### 3. 设置管理密码

本系统不存明文密码。在本机 PowerShell 执行（把「你的密码」换成实际密码）：

```powershell
-join ([Security.Cryptography.SHA256]::Create().ComputeHash([Text.Encoding]::UTF8.GetBytes('你的密码')) | ForEach-Object { $_.ToString('x2') })
```

复制输出的 64 位十六进制串 → Worker **设置 → 环境变量** → 添加：

| 变量名 | 值 | 建议 |
|---|---|---|
| `ADMIN_PASSWORD_HASH` | 那串哈希 | 勾选「加密」 |

> 部署后打开站点，未配置密码时会自动显示初始化向导。旧版明文 `ADMIN_PASSWORD` 变量仍兼容，但建议迁移。
> **忘记密码 = 无法找回**，只能重设环境变量（哈希不可逆）。

### 4. 添加定时触发器

Worker **设置 → 触发事件 → 添加 Cron 触发器**：

```
0 * * * *
```

每小时整点检查一次，足够用（同一订阅每天最多推一条）。

### 5. 配置通知渠道

打开站点登录 → **通知设置**：

- **Telegram**：[@BotFather](https://t.me/BotFather) 创建 Bot 拿到 Token；[@userinfobot](https://t.me/userinfobot) 查询你的 Chat ID；**先在 Telegram 里给你的 Bot 发送过 /start**，否则发不出来。
- **Server 酱**：[sct.ftqq.com](https://sct.ftqq.com) 获取 SendKey，推送到微信。

每个渠道可独立开关、独立测试，只有开启的渠道会收到提醒。

## 📖 使用说明

### 三个时间字段的关系

| 字段 | 含义 | 规则 |
|---|---|---|
| **通知时间** | 从这天开始提醒 | 必须 ≤ 结束时间；至多提前 365 天 |
| **结束时间** | 订阅到期日 | ≥ 今天；续费后改成新日期即可 |
| **连续通知** | 从通知时间起连发几天 | 1~365 天 |

**示例**：Netflix，结束时间 `2027-12-21`，通知时间 `2027-12-18`，连续通知 `4` 天：

→ 12 月 18、19、20、21 日每天推送一条，之后自动回到**待提醒**。
→ 明年续费后把结束时间改成新日期，新一轮提醒自动开始。

### 状态说明

| 状态 | 含义 |
|---|---|
| ⏳ 待提醒 | 未到通知期，或连发完等待下一轮 |
| 🔔 通知中 | 连发期内每天推送（只推已开启的渠道） |
| ✅ 已完成 | 已续费/已处理，不再推送 |

- 连发完不会产生「过期」状态，自动回到待提醒且**不会重复轰炸**；
- 手动把状态改回「待提醒」= 清零计数、立即重新开始；
- 修改结束时间 = 计数清零、开启新一轮。

### 推送消息样式

> **🟠 Netflix ｜ ⚠️ 只剩 2 天**
> 结束时间：**10月26日 周一**
> 本次提醒：第 2/4 天（10月23日 → 10月26日）
> 备注：合租账号
>
> ✅ 处理完请在后台标记「已完成」

- 首行状态按紧急度变化：🔔 常规 → 🟠 一周内 → 🔴 当天 → ⚫ 超期；
- 测试全部时多条订阅合并为一条消息，每张卡片带序号。

## ❓ 常见问题

**收不到推送？**
① 通知设置里渠道开关是否打开；② Telegram 是否给 Bot 发过 /start；③ 点列表里的 🧪 测试按钮实测——弹窗会显示每条渠道的发送结果和后端版本号；④ 发送失败时下个整点自动重试（连续失败会在日志体现）。

**界面好像是旧的？**
部署新代码后按 `Ctrl+F5` 强刷。页脚和测试弹窗都带版本号，可确认线上跑的是哪份代码。

**测试全部为什么是一条长消息？**
多条订阅会合并成一条带分隔线的消息推送（每张卡片带序号），单条测试才是完整卡片。

**通过反向代理 / 镜像域名访问正常吗？**
正常。跨站防护基于浏览器强制的 `Sec-Fetch-Site` 头，不比对 Origin，代理场景不受影响。

**数据存在哪里？**
全部在你自己 Cloudflare 账号的 D1 数据库里， Worker 不上报任何数据到第三方。

## 🔒 安全设计

- 口令只存 SHA-256 哈希，常数时间比较防时序侧信道
- 登录签发 64 位随机 Session 令牌（HttpOnly · Secure · SameSite=Lax，有效期 10 天），Cookie 不放密码
- 同一 IP 连续失败 5 次锁定 10 分钟（原子 UPSERT 实现）
- 全站 POST 校验 `Sec-Fetch-Site`，仅拦明确的跨站请求
- 全站安全响应头（nosniff / DENY / no-referrer），HTML 禁缓存

## 🧱 技术说明

- **单文件** [`1.js`](./1.js)：Workers fetch + scheduled 两个入口，粘贴即用
- **D1 四张表**：`subs`（订阅）、`config`（渠道配置）、`sessions`（登录会话）、`login_lock`（登录限速），自动建表与迁移
- **时区**：全系统以北京时间（UTC+8）为日界，按天去重不会重复推送
- **批量操作**：D1 单语句参数上限 100，批量删除/测试自动分批
- **版本指纹**：页脚与测试弹窗携带版本号，方便确认线上版本
